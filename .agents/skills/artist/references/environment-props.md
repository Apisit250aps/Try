# Environments and props

Use for visual world building and production assets, not location logistics,
architectural certification or manufacturing engineering. Source basis:
[background design](../research/sources.md#a04),
[perspective construction](../research/sources.md#a12), and
[look development](../research/sources.md#a13). The tests below are local synthesis.

## Environment workflow

Start with the supplied action and world rules. Identify usable paths, entrances,
landmarks, elevation and character-scale anchors. For a recurring location, a
simple plan or blockout can expose contradictions before a polished keyframe.
Mark invented geography provisional; preserve approved locations across shots.
A beautiful station painting that leaves no route to the platform fails its use.

Separate a mood/concept image from a reusable environment packet. As needed,
deliver a location ID/version, layout/scale sketch, key views, landmark labels,
materials, light/weather variants and unresolved surfaces. A single view need not
become a complete set package. Do not invent unseen rooms as approved canon.

Compose around the intended action: foreground overlap, middle-ground subject,
background structure, quiet space and detail density. Check that depth cues and
perspective agree with the projection. Architectural edges sharing a direction
should converge coherently; a rotated bench need not share the wall's vanishing
point. Reduce decorative detail that competes with the subject before moving a
story-critical landmark. Use [visual-development.md](visual-development.md) for
value, light and color decisions.

Example: a canal walkway needs a believable door/figure/bridge scale and a
continuous route. Counterexample: repeated windows getting larger in the distance
without a deliberate projection convention create inconsistent scale. Atmospheric
simplification may support depth, but do not blur pixel work or erase a required
sign to achieve it.

## Prop workflow

Identify purpose, owner, scale, grip/contact, operation and meaningful states
(open/closed, intact/broken, empty/full). Build a readable overall mass first,
then construction and surface treatment. Show additional views/callouts only
when the next maker cannot infer functional details from the main view.

A field notebook needs hinge/spine, page block and holding clearance; a brass key
needs a readable bow/shaft/teeth and a grip appropriate to its size. Surface
scratches cannot repair a handle that intersects the palm. For a scene prop,
record held anatomical hand and state rather than moving it for convenience.
If a required mechanism is unknown, label the proposal; a plausible drawing is
not a tested mechanism.

For reusable props, provide ID/version, dimensions or relative scale, neutral
material/color reference, relevant views and state variants. If animation or
compositing is requested, agree on separable parts and anchor conventions; do not
promise a rig or layered source that the tool did not produce.

## Camera and production collaboration

Send Director the intent, options and narrative implications; send Cinematographer
layout anchors, surface/light behavior and any occlusion constraint. Receive
framing/projection, screen direction, shot lighting and target aspect ratio.
[Layout practice](../research/sources.md#a15) demonstrates that these duties overlap
in production; this repository's role split is an interface choice, not a universal
studio organization.

When a locked angle hides the important object, first test pose/prop separation
within the frame. If that fails, offer an angle or blocking proposal with its
continuity impact. Keep the original shot viable where possible. Hand off stable
asset IDs and approved state changes to the next role using the
[production contract](production-contract.md); Artist does not silently reorder
shots, retime the action or add dialogue.
