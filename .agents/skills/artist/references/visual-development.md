# Visual development and design decisions

Use for new looks, key art and still-frame composition; skip exploration when
making a narrow approved edit. Principle origins: Disney's
[visual development](../research/sources.md#a01), Getty's
[elements](../research/sources.md#a05) and [design](../research/sources.md#a06).
The decision tests and examples below are this project's synthesis, not a studio
manual or universal formula.

## From intent to a visual hypothesis

Extract what the viewer should understand: subject/action, emotional tension,
world constraints and intended viewing size. Turn adjectives into visible choices.
For “lonely but hopeful,” try an isolated small figure with one readable warm
light ahead; test whether it reads as anticipation rather than abandonment.
“Cinematic, beautiful, detailed” alone gives no criterion for choosing a design.

For an unresolved recurring look, compare a few inexpensive hypotheses through
shape/value thumbnails or labeled written plans when drawing is unavailable.
Vary a meaningful variable: compressed versus open space, rigid versus flowing
silhouette, muted field versus a restricted color accent. Name what each option
communicates, its production cost, and a reason to reject it. Develop a useful
candidate before surface detail. Do not make the user approve every thumbnail
unless selection is necessary to define shared canon.

Use research to answer specific questions: how a tool is held, how a garment
fastens, how a location supports the action. Distinguish observation from
invention; a moodboard is neither permission to copy nor proof of cultural accuracy.
For culturally specific clothing, architecture or symbols, use relevant primary
records and practitioner/community input where needed rather than a collage of
unrelated motifs. See [creative development](../research/sources.md#a02).

## Composition and value

Decide the primary read and supporting read before ornament. Test at thumbnail
and actual delivery size. Group light/dark masses; use contrast, edge, scale,
spacing or detail selectively to guide attention. A grayscale preview can expose
value collisions but cannot prove that color coding is accessible.

| Decision | When / how | Trade-off and failure test |
| --- | --- | --- |
| Negative space | Separate an important hand/prop from torso; reserve caption space only when needed. | Too much isolation can weaken contact or intimacy. Check the actual gesture, not only the outer silhouette. |
| Balance and rhythm | Arrange major masses and repeated motifs around the intended read. | Symmetry can convey ritual/stillness; asymmetry can add tension. Neither is intrinsically better. |
| Depth and overlap | Establish foreground/subject/background, scale anchors and occlusion. | A foreground frame can add depth but hide story action. Check visibility at final crop. |
| Edge/detail hierarchy | Concentrate sharper edges or detail near the intended focus. | Uniform sharpness competes for attention; excessive softness removes necessary identity. |
| Tangency | Check near-touching contours and accidental alignments at hands, faces and rooflines. | Move or overlap clearly when ambiguity harms the read; do not “fix” purposeful graphic joins. |

Example: in a dark station, an intensely bright timetable can overpower the
waiting character. Reduce sign contrast or simplify its detail while preserving
locked geography. Counterexample: if reading the timetable is the requested
story action, suppressing it would undermine the brief.

## Perspective, color, light and materials

For constructed spaces, establish viewpoint/projection and a scale anchor before
detail. Check consistent convergence within each set of parallel edges; rotated
objects can use different vanishing points. Orthographic reference views preserve
scale rather than imitating a dramatic perspective shot. Use guides or a simple
blockout when a recurring set must work from several angles; mark it a proposal
if it changes a locked camera. [Krita perspective](../research/sources.md#a12)
provides construction support, not an obligation to use Krita.

Separate base surface color from illumination and display interpretation. Specify
light source/direction, softness, value range and the color relationship needed
for the brief. Test a neutral material view when lighting obscures a costume
match. A blue night pass does not authorize a new blue costume swatch.
Color keys can explore the supplied emotional progression; Artist does not invent
new story beats to justify the palette. See [lighting](../research/sources.md#a14).

Local diagnostics: compare a small subject against its actual background before
choosing a swatch; neighboring colors can change its perceived prominence. Reserve
saturation/temperature contrasts for the intended read rather than giving every
surface an accent. Keep cast-shadow direction consistent with the agreed sources;
use softer or harder transitions according to the light and rendering language.
“Warm means happy” or “blue means sad” is not a substitute for testing the scene.
A backlit silhouette may express isolation well yet conceal required facial
acting; consider a controlled fill or different value arrangement within the
shot contract and explain the compromise.

For materials, compare broad color, surface relief and reflection behavior
separately, as informed by [look development](../research/sources.md#a13).
Local drawing heuristic: establish form and light first, then use selective
highlight shape, edge treatment and texture scale to differentiate metal, cloth,
wood or stone. A scratched brass key needs readable metal and a usable bow before
microscopic scratches. Flat/pixel styles translate these cues into their own
rendering rules; physical realism is not a requirement for every design.

For repeated exports, record working/output profile and any view transform when
known; use the same viewing conditions when comparing. Do not infer a profile
from file extension or a palette hex from a shaded pixel. Ask a printer for its
output contract rather than inventing CMYK settings.
[Color management](../research/sources.md#a16) explains why file values and
appearance must be distinguished. Technical color settings do not rescue a weak
value structure.

## Style bible as a usable constraint

Use the [art bible](../templates/art-bible.md) for decisions needed again:
shape/proportion rules, line hierarchy, palette roles, lighting exceptions,
material samples, detail budget, perspective conventions and examples of drift.
Include a reason and visual counterexample where a rule is easy to misapply.
Record reference roles and versions. A folder of admired pictures without rules
cannot resolve a conflict between two artists.

For a new look, test the proposed rules on a character, a relevant prop and a
small environment study only when the project needs that range; do not mandate
three assets for an icon request. Check that the same language works across
scales and moods. Keep exploration, selected design and production specification
separate. Use [review-rubric.md](review-rubric.md) before calling an asset reviewed.
