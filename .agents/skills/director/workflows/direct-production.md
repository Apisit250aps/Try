# Direct a production or revision

Use only the stages required by the request. The bounded loops, dependency model
and dispatch rules are **local system design**, P12–P14 in
[notes](../research/notes.md); craft checkpoints draw on P01–P11.

## Standalone vs orchestration

Discover actual tools/capabilities and applicable authorization. A skill is
instructional context; it does not launch agents. If delegation is available and
authorized, assign a real specialist by capability, input version, output ownership
and acceptance check. Otherwise deliver the requested standalone work and explicit
pending briefs, or use an available tool yourself within scope and label that work.
Never report parallel execution, dispatch, success or specialist review from a plan.

Before editing, inspect repository/workspace status, role boundaries and current
artifacts. Give each real delegate its files/responsibility; tell it others are
working and not to overwrite their edits. Use isolated outputs or distinct owned
paths. Do not reset, stash, commit, publish or edit shared canon merely to simplify
coordination. Follow actual user authorization for any such action.

## Development and preproduction

1. Establish the brief, source-of-truth versions and authority. Draft treatment,
   audience journey and scene intent; separate open choices from locks.
2. Resolve causality/canon/script contradictions before dependent final plans.
   Cite the conflicting fact and proposed action. Offer a canon-preserving option
   plus a separate change proposal to the right owner/user. Continue unaffected work.
3. Assign discovery work in parallel when independent: Artist look explorations
   and Cinematographer coverage alternatives can use the same approved intent, but
   must state provisional shared geometry/light/material assumptions. Reconcile
   them before final layout/assets. Do not let two roles edit the same bible.
4. Stage/rehearse or specify boards/previs/animatic to answer risky questions:
   clue readability, partner reaction, contact, spatial continuity, rhythm. Make
   simple experiments before expensive final generation. Actual viewing/measurement
   is required before claiming the experiment succeeded.
5. Select a feasible interpretation; protect essential audience evidence and
   performance. Ask Producer/user for actual budget/schedule constraints; record
   estimates, unknowns and contingency. A plan is not a purchase or booking.

## Production and postproduction

Maintain scene entry/exit, performance arc, asset/look state, approved deviations
and actual take/clip IDs. Review dailies/returns when provided, giving one prioritized
creative adjustment and a concrete acceptance check. New generated outputs remain
uninspected until viewed; inspect time-dependent artifacts over time, not just a
poster frame. Use real exposed generation metadata; do not invent seed/model/settings.

With Editor, evaluate assembly → sequence/context pass → fine rhythm; with Sound
Designer, test perspective/cues/silence and picture interaction. Artist/Cinematographer
address visual failures. Stage names are convenient conventions, not enforced
waterfall gates; sound and edit exploration can feed earlier choices. Review final
creative intent on the actual version/export, plus delivery/rights/accessibility
needs where applicable. A text-only task may finish at a reviewed treatment.

## Conflicts and actionable notes

Translate competing solutions back into the protected experience. An Artist's
low-contrast fog look and a Cinematographer's sharp clue lighting can coexist if
only the clue needs separation; try local value/position/hold changes before a
global look replacement. Compare costs and losses. Within authority, Director
selects the creative trade-off and logs dissent; owners implement their artifacts.
If requirements conflict or the choice would change canon/reserved scope, escalate
one decision with alternatives and a recommendation. Do not count votes or give
Director unlimited veto over safety/user requirements.

Critic findings are observations/hypotheses/recommendations, not automatic orders.
Check the cited version, intention and evidence; accept, modify, test, defer or
reject each consequential note with reason. Preserve independent findings even
when disagreeing. A missing Critic means only self-review is possible.

## Bounded revisions and failure recovery

Agree a revision/resource allowance for expensive work. For a small text task with
no supplied limit, use **up to two focused revision passes after the initial draft**
as a local default, not a craft standard; stop earlier when acceptance is met.
Each pass needs a named defect/hypothesis, owner, changed artifact IDs, acceptance
test and cost estimate. Don't restart all specialists for an isolated note.

Stop and return the best current artifact plus options when criteria pass, the
allowance is spent, the same failure recurs without new evidence, or authority/
input/tool is missing. Report a blocked dependent step, not a completed production.
A hard failure may not be waived by “the loop is over”; propose a reduced scope or
request the necessary decision. New cost/release needs approval only as applicable;
elapsed time and silence are not authorization.

For generation failure: retain the failed result/evidence, diagnose provider vs
prompt vs reference vs inherently complex action; simplify one variable, reduce
motion/contact or use an approved held pose/cutaway/limited-animation alternative.
Protect causal evidence and reveal order. Check current provider documentation
before relying on exact duration, controls, reference support or negative prompts.
Do not retry unchanged indefinitely or quietly increase spend. No provider is
mandatory. Runway S12 is one version-specific example, not a universal constraint.

## Selective invalidation

Record edges **upstream ID@version → dependent ID@version → consumed fact/function**.
On change, compute the transitive affected set, then assess each edge:

1. Keep prior artifacts; record authorization, changed facts and invariants.
2. Mark direct dependents stale/unresolved, follow their dependent edges and
   invalidate the relevant approval scopes. Do not erase unrelated approvals.
3. Determine which dependents need regeneration, re-edit, inspection only, or no
   change with a stated impact rationale. An identical consumed invariant can
   remain valid after a documented check; never silently relabel an old base.
4. Reconcile incoming parallel work against its original base and current facts.
   Quarantine obsolete portions; reuse valid work with provenance. No last-writer-wins.
5. Rerun from the earliest changed meaning forward, only where needed. Capture
   new receipt/inspection/approval evidence; planned re-review is not clearance.

Examples: changed canon knowledge can affect scripts, reaction/performance notes,
shots, generated clips, sound cues, cut and later episodes. Changed prop silhouette
can affect clue framing/occlusion, animation contact and edit readability. A shot
reorder can affect information, sound perspective and rhythm without changing the
prop design. Check actual dependencies rather than always rebuilding everything.
